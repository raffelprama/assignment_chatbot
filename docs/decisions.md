# Technical decisions

Each entry: the decision, what was rejected, and the reason — with the evidence where it was measured.

| # | Decision | Rejected | Reason / evidence |
|---|---|---|---|
| D1 | **Retrieval unit = one numbered section, served verbatim.** Question keys and document maps only point at sections | Fixed-size character chunks; serving LLM-written Q/A answers | Answers must not mislead and must be traceable. The SOPs are section-structured (4 × 8 numbered sections). Quoting the verbatim section keeps numbers like "15 menit" exact |
| D2 | **Route each page on text quality** (length, glyph ids, letter ratio); pages without a usable text layer go to a vision LLM | Trusting any text layer; Tesseract OCR | KB_01/KB_04 are 122-dpi image-only pages. Vision transcription matched the hand transcription exactly (CER 0.0000) and matched the true text layer of KB_02/KB_03 exactly when forced on them (`eval/reports/extraction.md`). Tesseract needs system installs and works best around 300 dpi |
| D3 | **Column-aware reading order from text-run coordinates** | Trusting the PDF content-stream order | Measured on KB_03: a top-to-bottom reader interleaves §1 with §7 and loses §7–§8 as sections; the column-aware reader recovers all 8. The validator detects the splice |
| D4 | **Validator fails ingestion loudly** (empty sections, another section's heading inside a body) | Indexing whatever came out | A silently mis-ordered page is the worst failure for a "trustworthy" assistant |
| D5 | **Deterministic citation check** before an answer is shown: the cited section was retrieved and the quote is a verbatim substring | Trusting the model's citations | Criterion "traceable to document and page". It cannot fail open: no valid citation ⇒ `no_answer`. Unit-tested with fabricated quotes |
| D6 | **Five outcomes** — `answered`, `partial`, `no_answer`, `out_of_scope`, `unsafe` — always HTTP 200; dependency failures are 503 | Binary answer/refuse; errors disguised as "not found" | Many SOP questions are half-covered (e.g. "retention period" — a policy is named, no duration). `partial` + `missing` is the honest answer |
| D7 | **Hybrid retrieval** (Gemini dense + local BM25 sparse, client-side reciprocal rank fusion) | Dense only | Literature and the reference system favour hybrid; BM25 keeps exact tokens like `P1`, `SEV2`, `OTP`. **On this corpus the measured benefit is nil** (all configurations Recall@3 0.92–0.95, `eval/reports/retrieval.md`); kept because it costs one extra in-process query and protects exact-token matches on larger corpora |
| D8 | **BM25 tokenizer keeps short tokens** (`p1`, `sev1`, `otp`, `pic`) | Default tokenizers that drop tokens under 3 characters | In these SOPs the short codes are the most discriminative words. Pinned by a unit test |
| D9 | **Question keys** (5 per section incl. one English) generated at ingestion, constrained to questions the section fully answers | No keys; free Q/A pairs as the answer | Your requirement (Q/A format, higher match probability). Measured gain here is small (+0.01 Recall@3) because the corpus is tiny; they also give operators a CRUD lever (`/rag/keys`) to fix a missed phrasing without editing the source |
| D10 | **Deterministic document map** per document | LLM-written summaries | "Which SOPs exist / what does this SOP cover" needs a source that spans sections; $0 and exact |
| D11 | **Normalize step** with a scope card (all section titles), Indonesian search query, answer language; refuses only the clearly off-domain | No normalize; a blind topic classifier | English questions need an Indonesian query for BM25. A classifier that sees the section titles refuses fewer valid questions. Failure to classify continues the turn instead of refusing |
| D12 | **LLM judge with one bounded retry** that changes the input: widen retrieval (k 3→8) for incomplete/irrelevant, regenerate with the unsupported claims for unsupported | No judge; unbounded regenerate loops | Regenerating from the same evidence rarely fixes incompleteness; the tiny KB makes widening cheap. On judge outage the citation-checked answer is still returned, flagged |
| D13 | **LangGraph** for the chat turn | Plain async functions | Requirement. Gives typed state, explicit routing and per-node timings; five nodes would also fit in plain functions |
| D14 | **`gemini-3.5-flash-lite` for every LLM step**, fallback chain `gemini-3.6-flash` → `gemini-3.1-flash-lite` | `gemini-2.5-flash` | Probed on the free tier: 2.5-flash allows 20 requests/day (exhausted during development); 3.5-flash-lite ~1.5–2 s per call, no thinking tokens, correct structured output; 3.5/3.8-flash returned 503/504. The committed extraction artefacts were produced with 2.5-flash before its quota ran out |
| D15 | **Free-tier resilience**: requests-per-minute limiter, retry honouring the provider's "retry in N s", exhausted models skipped, persistent embedding cache | Plain retries | Observed: 100 embedding requests/min (each batched text counts), daily generate quotas, transient 503s. A daily-quota hint ("retry in 59827s") must not stall a request |
| D16 | **Qdrant Cloud** by default; embedded local mode (`QDRANT_LOCAL_PATH`) and docker-compose as alternatives | Server only | The provided credentials use a cloud cluster; local mode lets a reviewer run without any Qdrant server (verified by the test suite, which runs on in-memory Qdrant) |
| D17 | **Artefacts committed** (`data/extracted/*.json`) | Re-extract on every install | Re-indexing then needs only embeddings — no vision or key-generation calls, which matters on a free tier |
| D18 | **SQLite registry** for documents/jobs | Job state in Qdrant payloads | Job state is not vector data |
| D19 | **Deterministic point ids** (`uuid5` of file hash, kind, section, key index); write new version → verify → delete old | Random ids; delete-then-write | Re-ingest is idempotent; a failed re-index never empties a document |
